1. Owner Setup (One Time)

Ledger is a personal Telegram bot that helps you track four areas of daily life: study sessions, gym workouts, diet & nutrition, and daily habits. Its records live in a local SQLite database on your machine; messages still pass through Telegram during normal bot use.

For the household operator

Only the person who runs the bot needs this section. If your spouse has already added you, skip to First Run & Basic Navigation and message the bot directly.

Prerequisites

  • Python 3.14 — the tested deployment version
  • A Telegram account
  • A Telegram Bot Token (free, from @BotFather)
  • Your Telegram User ID (from @userinfobot)

Setup Steps

Create Your Bot

Open Telegram and message @BotFather. Send /newbot, choose a name and username. Copy the bot token it gives you.

Get Your User ID

Message @userinfobot on Telegram. It will reply with your numeric user ID (e.g., 123456789).

Install Dependencies
cd 12_ledger
python -m venv .venv
.venv\Scripts\activate        # Windows
pip install -r requirements.txt
Configure .env

Copy .env.example to .env. The operator adds both household users; everyday users should never need to edit this file:

BOT_TOKEN=your-token-from-botfather
ALLOWED_USER_IDS=<user-a-id>,<user-b-id>
TZ=Asia/Kolkata
REMINDER_HOUR=20
DB_PATH=ledger.db

Fast-action rollout and the external backup destination are operator settings documented in .env.example and the operations runbooks.

Start the Bot
python -m bot

The bot is now running. Open Telegram and message your bot!

💡 Security & Privacy

Only user IDs listed in ALLOWED_USER_IDS can interact with the bot, and only in a private (direct) chat; group and unauthorized messages are ignored. Each user’s logs, analytics, reminder opt-in, and food preferences are isolated; the routine, catalog, bot process, and host settings are shared. Messages still travel through Telegram, and the person operating the machine/database can inspect both ledgers and their backups.

3. Logging Study Sessions

Track what you study, for how long, and add optional notes. Every session is stored with a timestamp.

Quick Log (Shortcut)

Log instantly with a single message — no back-and-forth:

/study <subject> <minutes> [notes]

Examples:

In a quick log the duration must be unambiguous. A single number works anywhere — /study maths 45 revised trig. If your notes also contain a number, mark the duration with m — /study physics 60m reviewed chapter 2 — otherwise the bot asks you to clarify instead of silently guessing the wrong one.

5. Logging Meals

Track what you eat across four meal types: breakfast, lunch, dinner, and snacks. Calories and protein/carbohydrate/fat macros are required on every meal — usually supplied for you from a saved food, recipe, or the shared catalog.

Quick Log

/diet <meal> <food> [calories] [p=<g> c=<g> f=<g>]

Use + to separate multiple food items (they'll be converted to commas):

CommandWhat it logs
/diet lunch dal+rice 650Lunch: dal, rice — 650 cal
/diet lunch dal+rice 650 p=25 c=80 f=15Lunch: dal, rice — 650 cal; 25 g protein, 80 g carbs, 15 g fat
/diet breakfast oats+bananaBreakfast: oats, banana — no cal
/diet snack almonds 200Snack: almonds — 200 cal

Guided Meal Builder

Tap 🍽️ Log meal on Home or send bare /diet. Choose the meal type, then pick a saved item, search the bundled local catalog, or choose ✍️ Type it instead. A structured item goes through quantity and nutrition preview before joining an editable multi-item draft; you can add, change, remove, and finally ✅ Save meal. Calories and macros are asked only for a free-text item — a food, recipe, or catalog item already carries them. At the macro prompt, send protein, carbs, and fat in that order (for example, 25 80 15). All three are required.

📒
Ledger Bot
/diet
🍽️ Log Meal

Which meal?
🌅 Breakfast 🌞 Lunch
🌙 Dinner 🍿 Snack
💡 Nutrition is required

Every meal needs calories and protein, carbs, and fat. There is no /skip — tracking macros is the whole point, and a meal saved without them quietly under-reports your day with no way to tell later whether a blank meant zero or unknown.

You rarely type them. Log a saved food, a recipe, or a catalog item and the app calculates all four from that stored definition. Add a food once — /food add oats per=100g kcal=389 p=16.9 c=66 f=6.9 — and every future 100g oats fills itself in. Only a genuine one-off needs the numbers typed.

The app never estimates nutrition. If a food isn't saved and isn't in the catalog, it is reported as not logged with the reason, rather than guessed at.

💾 Keep what you typed

When a meal you typed out is saved, the Log another meal? keyboard carries an extra row — 💾 Save “<name>” — for each typed item that isn't already one of your foods. One tap turns it into a saved food priced at exactly what you just logged, so the second time costs a tap instead of a name and four numbers.

The food is defined as one helping: 1 portion buys the calories and macros you entered, 2 portions buys double. No gram weight is invented, because you never gave one — if you want the food measured by weight instead, save it yourself with /food add. That portion is also stored as your usual amount, which is what makes the food a one-tap ⚡ row in the meal picker afterwards.

Nothing about the meal changes: this only writes to your food list. The button keeps working after the flow times out, and it is never offered for a name you have already saved — it will not overwrite an existing food.

⚖️ Macro Tracking

Macros are required and measured in grams. Quick logs use all three case-insensitive labels p=, c=, and f= together with calories; guided logs take the three values in protein/carbs/fat order. Because every meal carries them, daily and weekly totals are complete rather than "known values only". Entries made before this rule may still be partial, and summaries continue to flag those honestly.

Saved Foods & Recipes

Save nutrition once, then scale it by weight, volume, pieces, or a food-specific portion. Keys are a single token of ASCII letters and numbers; hyphens and underscores are also supported, and kebab-case is recommended for names with multiple words.

/food add apple per=100g kcal=52 p=0.3 c=13.8 f=0.2
/food portion apple medium=182g
/food unportion apple medium
/food list
/food show apple
/food remove apple

All four of kcal=, p=, c=, and f= are required — a saved food is a definition every future log inherits, so a gap in it becomes a gap in every meal that uses it. Use 0 for a nutrient the label really shows as zero. Saving an existing key replaces its nutrition profile. A named portion is specific to its food: for example, medium=182g belongs to the saved apple definition.

/recipe add chicken-curry yield=4serving
/recipe ingredient chicken-curry food:chicken 500 g
/recipe ingredient chicken-curry food:oil 14g
/recipe removeitem chicken-curry food:oil
/recipe list
/recipe show chicken-curry
/recipe remove chicken-curry

Recipe ingredients retain their resolved base quantity, so changing a named portion later does not silently rewrite a recipe. Updating a food's nutrition affects future recipe logs, while completed diet logs remain unchanged snapshots.

Use explicit food: and recipe: references when logging. This keeps the original quick-log syntax unambiguous:

/diet snack food:apple 1 medium
/diet snack food:apple 220 gm
/diet dinner recipe:chicken-curry 1 serving
📐 Unit Rules

Common aliases such as g, gm, kg, ml, and litre are normalized automatically. Named portions must exist on that food. Ledger never guesses a cross-dimension conversion; you must configure it explicitly on that food, for example piece=50g or ml=1.4g. A recipe can be logged by mass or volume only when its yield uses the same dimension.

⚠️ Streak Rules

• A streak counts consecutive days with a check, starting from today and going backward.

• If today is unchecked, your streak is 0 — even if you had 100 days before.

• Un-tapping a habit (tapping a ✅ row) deletes the record for that day.

• Use the yesterday toggle to fix forgotten check-offs and save your streak!

💡 Re-adding Habits

If you remove a habit and later add one with the same name — case and spacing don't matter, so "read" matches "Read" — the bot reactivates the original instead of creating a duplicate. Your streak and history are preserved.

Amounts can lead or trail — 100g oats and oats 100g both work — and items are separated by commas. Nothing is saved until you tap a meal type.

🎤 Optional voice notes (off by default)

If voice is switched on for this bot, you can send a voice note from Home instead of typing. The bot writes back what it heard, then shows the same preview and the same meal-type buttons — nothing is saved until you tap one.

Your recording never leaves this machine. It is transcribed on the computer running the bot and deleted immediately afterwards. It is never stored and never attached to your log. That is exactly why speech is handled locally even though meal text can optionally be sent to an AI parser.

Notes are capped (60 seconds by default) — a meal is a sentence, not a monologue. Send voice notes from Home, not in the middle of a guided flow; mid-flow the bot will ask you to finish or /cancel first. If voice isn't installed, the bot says so and you can type instead.

🤖 AI help reading meals (on by default)

If the bot is configured with an AI key, phrases it can't read locally — like "two eggs and a slice of toast" — are sent to be split into items for you. This is on by default. /aiparse off turns it off for you at any time, and that choice is yours alone: it is stored per person, and the default never overrides it. /aiparse on its own tells you which state you are in and whether you chose it.

What is sent: only the part of your message the bot couldn't understand, whether you typed it or spoke it. Your logs, totals, name, and Telegram ID are never sent. Items the bot already understood are not sent either.

What the AI cannot do: supply any calorie or macro number. It only splits your words into items; every nutrition figure still comes from your saved foods or the shared catalog. You still confirm the meal before it saves, and the preview tells you when AI helped.

💡 Why some items are left out

Nutrition always comes from your saved foods or the shared catalog — it is never estimated. An item is left out when it is unknown (add it with /food add), has no amount, uses an unsupported unit, or matches more than one thing. In the last case the bot shows you the candidates rather than picking one, so a meal never contains food you didn't eat.

7. Tracking Supplements

Supplements work like habits — set them up once, then check them off each day — but each one can also record a dose and a timing, so the checklist shows what you actually take.

💊 Supplements never affect calories or macros

This section tracks adherence only: whether you took something on a given day. A supplement has no calorie or macro values, is never part of a meal, and never changes any nutrition total or chart. If you want something counted as food, log it as a meal instead.

Taking Something More Than Once a Day

A single tick cannot say "one of the two scoops I aim for". So in /supplements setup, each supplement has a 🎯 button that sets a daily target. Pick 2×, and its checklist row starts counting instead of toggling:

📒
Ledger Bot

Tap to check off:
🔸 Creatine 1/2 ➖
⬜ Magnesium
A second tap is a second scoop, not an undo

On a counted row, tapping the name adds one — that is the whole point, so it never quietly removes the one you just took. Use ➖ to take one back off; at zero the day's record goes away entirely, exactly as if you had never tapped. Going over the target is fine and is recorded as it happened (3/2 still shows ✅).

The day counts as taken — in the header and in the streak — only once you reach the target, so a half-finished day reads as outstanding. Set the target back to 1× (off) at any time and the row returns to a plain tick; days you already recorded keep the counts they were given.

8. Logging Your Weight

Weight is the one thing here that is a measurement rather than a record of something you did, so it works a little differently: one number per calendar day, and weighing again corrects that day rather than adding a second entry.

Logging It

Tap ⚖️ Weight on Home, or send /weight. The bot offers five numbers around your last weigh-in — most days one of them is the reading, and that is a single tap. Any day it isn't, type the exact number.

📒
Ledger Bot
⚖️ Weight
⚖️ Today's weight

Last weigh-in: 72.4 kg (yesterday).
Tap one, or type an exact number.
72.2 72.3 72.4 72.5 72.6
72.3
⚖️ 72.3 kg logged for today.
📈 7-day average 72.5 kg · −0.2 kg vs the week before

In a hurry, /weight 72.4 does the whole thing in one message — there is no flow to leave afterwards. Typing works the way you would expect: 72, 72.4, 72,4, and 72.4 kg are all read the same way.

⚖️ Missing a day is fine — that is the design

The chart and the 7-day average carry your last reading forward across days you didn't weigh, for up to 10 days. After that the line breaks until you weigh again, on purpose: a flat line across a month of silence would read as "my weight held steady", which is a claim about your body rather than about your record.

Carried days are drawn as hollow dots and measured days as filled ones, so you can always see which is which.

Reading The Trend

/chart weight (or ⚖️ Weight Chart under Analytics) draws the last 30 days with the 7-day rolling average on top. The average is what to watch: a single day moves on water, salt, and timing, so the week-over-week comparison is the smallest honest statement about a direction.

💡 Weigh at the same time of day

First thing in the morning, after the bathroom and before breakfast, is the usual advice — not because that number is more "real", but because comparing like with like is what makes the trend mean anything.

Recorded the wrong number? Just log the right one — the day is corrected and the bot tells you what it replaced. Recorded a weight on a day you did not actually weigh? Open /weight and tap 🗑 Clear today's weight, so the fill carries your last real reading across that day instead of standing on an invented one.

10. Reminders & Routine

Ledger can nudge you, not just record you. Reminders are opt-in for each person; once enabled, Ledger can send one evening habit reminder. Add an optional routine.yaml and it becomes a lightweight daily coach that reacts to what you have — and haven't — logged.

The Evening Habit Reminder

Reminders are off for a new user until that person sends /reminders on. When enabled, and when no routine file replaces the schedule, the bot currently checks every evening at 8:00 PM in the configured timezone and lists unchecked habits:

📒
Ledger Bot
⏰ Evening Reminder

You still have 2 habits unchecked today:

⬜ Read 30 min
⬜ No Sugar

Tap /habits to check them off!

If all habits are done, you get a congratulations message instead: 🎉 All habits done today!

💡 Customizing the Time

Change REMINDER_HOUR in .env (0–23, local time) — e.g. REMINDER_HOUR=21 for 9 PM. Note: if you add a routine (below), it replaces this single reminder, so put your habit check in the evening anchor instead.

Routine Anchors Optional

A routine turns the bot into a feedback loop. You define a few anchor moments in a routine.yaml file; at each one the bot checks that day's logs — celebrating what's done, nudging what isn't — and can add a rotating motivational quote. Copy routine.example.yaml to routine.yaml, edit it, and restart the bot.

# routine.yaml
quotes:
  - "Discipline equals freedom."
  - "You don't have to be extreme, just consistent."

targets:
  study_min: 60
  gym_days: [Mon, Wed, Fri, Sat]

anchors:
  - { id: morning, time: "08:00", emoji: "☀️", title: "Morning kickoff", checks: [], quote: true }
  - { id: midday,  time: "14:00", emoji: "🔎", title: "Midday check-in", checks: [study, diet], quote: false }
  - { id: evening, time: "21:00", emoji: "🌙", title: "Evening review", checks: [habits, study, gym, diet], quote: true }
FieldWhat it does
time24-hour local time the anchor fires (once per day)
checksAny of study, gym, diet, habits — each adds a log-aware line. An empty list is a pure motivational push.
quotetrue appends the day's rotating line from quotes
targets.study_minReports study as on-track vs. behind against this daily goal
targets.gym_daysOnly nudges the gym on these days; other days say "rest day"

💡 Good to Know

• A routine replaces the configured evening reminder — include habits in your evening anchor to keep the habit nudge (it arrives as a second, tappable message, shown above).

11. Utility Commands

/undo — Undo Last Entry

Made a mistake? Send /undo to review your most recent log entry (study, gym, or diet). The bot shows it and waits for you to confirm — nothing is deleted until you tap “Yes, undo.” Only works within 24 hours of the entry.

⚠️ How Undo Works

• Preview first — /undo deletes only after you tap Yes, undo; tap Keep to dismiss.

• It removes that exact previewed entry, so tapping again (or after a network hiccup) is safe — it will never delete a newer entry by mistake.

• Works on study, gym, and diet logs only — not habits. To undo a habit check, tap its checked ✅ row again.

• Entries older than 24 hours cannot be undone.

• Finish or cancel a guided log before using /undo.

/recent — Reconcile a Save

Send /recent to see your latest study, gym, and diet entries, newest first. It's handy when a confirmation didn't arrive (e.g. a network hiccup) and you want to check whether a log actually saved — without guessing and logging it twice.

💡 Saves are replay-safe

If Telegram re-delivers the same message after a reconnect, the bot recognizes it and does not create a duplicate. Genuinely repeating an activity (sending the command again yourself) still logs a new entry by design — use /recent to confirm before re-sending.

/settings, /reminders, and /suggestions

Reminders are opt-in per person. A newly added user receives no scheduled messages until they turn them on:

• /reminders on — start receiving daily nudges and routine anchors.
• /reminders off — stop all scheduled messages.
• /settings — see reminder and suggestion state, routine profile, and—when fast logging is enabled—quick-bar/usual status.
• /suggestions on — rank your own choices from your private history, recency, and pins.
• /suggestions off — list private foods/recipes alphabetically.
• /suggestions reset — clear pin/hide ordering preferences without deleting usual amounts or logged history.

Your ledger, analytics, reminder opt-in, and food preferences stay separate from your spouse’s. The routine schedule, shared food catalog, bot process, and host configuration are household-wide.

/suggest — Tell the Bot What to Change

Anything you send after /suggest is filed as a suggestion for whoever maintains this bot. It is not a log entry: it changes no total, no chart, and no streak.

• /suggest let me log water — files it in one message.
• /suggest on its own — shows what you have already sent, then waits for your next message. Easier on a phone than typing the command and the thought together.

💡 Worth knowing

• Every word after the command counts. Nothing is treated as a keyword — /suggest list files the word “list” as your suggestion, because guessing at subcommands would swallow a real one.

• Say it however you like. There is no format to follow, and the text is stored exactly as you wrote it, line breaks included (up to 1000 characters).

• 🗑 Withdraw takes it back, at any time — it is your suggestion, not a log entry with a 24-hour window. The button only works for the person who sent it.

• /suggest and /suggestions are different commands. The plural one, above, orders your food list; the singular one sends an idea about the bot.

/cancel — Abort Current Conversation

If you're in the middle of a guided log and want to stop, send /cancel. This works in every conversation flow (study, gym, diet, habit setup).

Conversation Timeout

If you start a guided log and don't respond within 15 minutes, its unfinished part is cancelled. Study and an incomplete gym exercise show a restart prompt; a Diet timeout names the discarded draft and confirms that it was not logged. Gym exercises already completed earlier in the same workout remain saved.

Fast logging from the quick-action bar

When fast logging is switched on for you, Home also sends a small persistent bar under the message box:

Tap 🍽️ Meal to log, or 🔁 Repeat last meal.
Meal Repeat last meal

🔁 Repeat last meal re-logs your most recent meal as an exact copy — the same items, the same nutrition as recorded then. Home shows which meal that is, so there is no guessing. Nothing is re-calculated, and the receipt that comes back has ↩️ Undo for that one meal (within 24 hours).

🍽️ Meal opens the picker. Two kinds of row look different because they behave differently:

RowWhat one tap does
⚡ Banana · 1 medium Logs it immediately at the amount shown — that is your saved “usual”. A receipt with ↩️ Undo follows.
⚡ Chicken curry (recipe) · 1 serving Same, for a saved recipe.
🥗 Banana Asks how much first — no usual is saved for it yet.

🕒 What Meal assumes

The fast Meal button starts with a meal type based on local time: breakfast from 04:00–10:59, lunch from 11:00–15:59, dinner from 16:00–21:59, and snack at other times. Tap 🕒 Change meal type in Quick Meal to change it. Home’s Log meal builder asks for the type before you add food.

To create a usual, tap ⚙️ beside a saved item and set the amount. In the guided /diet builder the same items never log on one tap — there, every row asks for an amount, because a builder meal is saved deliberately at the end.

After selecting one of your own saved foods or recipes, its quantity screen also offers 📌 Pin and 🙈 Hide. Pinning promotes it in suggestions; hiding removes it from suggestion lists. These controls do not alter past logs or the saved usual, and shared catalog foods do not expose them. /suggestions reset clears all such pin/hide choices.

Meal receipts: repeat or correct the exact meal

Fast meals and exact Repeat return a durable receipt. Its buttons refer to the meal shown on that receipt, not whichever meal happens to be newest later:

Receipt actionWhat it does
↩️ Undo Removes that exact meal within 24 hours. Pressing it twice is harmless, and it remains targeted even if you logged another meal afterward.
🍽️ Log another Starts a fresh Quick Meal without changing the completed receipt.
🔄 Log again at today’s values For structured foods/recipes, recalculates from their current definitions and previews every difference before saving. If an item can no longer be resolved, you must explicitly keep its original snapshot or remove it.
🔁 Repeat and “today’s values” are intentionally different

Repeat last meal copies the old recorded snapshot exactly. Log again at today’s values recalculates and asks you to review the result. Neither silently rewrites the original meal.

🔎 A search with no matches

You get three buttons instead of a dead end: ◀️ Back to my items, 🔎 Search again, and ✍️ Type it instead. Typing another word still works too, and your draft is untouched either way.

/keyboard hide puts the bar away for now; /keyboard show restores it only if your account is eligible. Hiding is momentary — the bar may return on the next eligible Home response.

13. Tips & Best Practices

⚡
Use Shortcuts
After the first week, you'll find shortcuts (/study maths 45) much faster than the guided flow. They're one message instead of three.
🌙
Check Habits Before Bed
If you opted in, use the configured evening reminder as your cue. If you miss it, use the ← Yesterday toggle before the following midnight.
📊
Weekly Reviews
Run /summary week every Sunday. Check your study hours, gym frequency, and habit completion rate. Spot trends before they become problems.
🔥
Protect Your Streaks
Streaks are fragile — one missed day resets to zero. Start with easy habits (like "drink water") to build momentum.
🍽️
Log Meals As You Eat
Don't batch your diet logs at night — you'll forget items and undercount. The shortcut makes it a 5-second task.
💾
Backup Your Database
The live database uses SQLite WAL mode, so never copy ledger.db by itself. The operator uses python -m scripts.backup_db with an explicit external destination and follows docs/backup_runbook.md. Never sync a plaintext backup to cloud storage.

14. Troubleshooting

ProblemSolution
Bot doesn't respond Check that the one supervised bot process is running. Check its terminal/service log and verify your user ID is in ALLOWED_USER_IDS. Do not start a second copy beside an already-running service.
Bot ignores me in a group By design — Ledger does not respond in group chats. Message the bot directly instead.
"Something went wrong" error Check the terminal logs for the full traceback. Try /cancel to clear any stuck conversation state, then retry.
Commands are unresponsive You might be in a stuck conversation. Send /cancel first, then try your command.
Wrong date on entries Check that TZ in .env is set correctly (e.g., Asia/Kolkata for IST). Restart the bot after changing.
Reminder not arriving Send /settings first and use /reminders on if needed. The bot must be running. If routine.yaml exists, its anchors replace REMINDER_HOUR; otherwise verify that hour and the configured timezone. A transient network failure is retried.
Routine not firing / bot won't start If routine.yaml exists it replaces the single reminder. On a mistake the bot refuses to start and names the bad line — fix it and restart. Remove the file to fall back to the REMINDER_HOUR evening reminder.
Charts look empty Charts show data from the last 7 (or 14) days. If you just started, log a few days of data first.
Bot dies when machine sleeps Polling pauses while the chosen host sleeps. Use the documented NSSM/Scheduled Task or systemd supervision on that host so one process restarts cleanly; a separate server is not required for this two-person app.
Quick-action bar is missing The bar is rollout-controlled. /keyboard show works only for an eligible user; otherwise continue from Home’s inline buttons and ask the operator to check the quick-action rollout settings.
No ⚡ instant rows appear An instant row requires a private food or recipe with a complete saved usual. Create the food with /food add, open Quick Meal, tap its ⚙️ control, and save an amount. Shared catalog items do not support usuals in this build.
Adding your spouse The operator adds both Telegram IDs as a comma-separated ALLOWED_USER_IDS list, then restarts the bot. Logs, analytics, reminder opt-in, and food preferences stay separate; the bot’s routine, catalog, and host settings are shared.
📁 Your Data

Ledger records are stored locally in ledger.db (SQLite), and nutrition lookup stays local. Messages still pass through Telegram as part of normal bot operation. Inspect only a stopped database or a verified backup with a SQLite browser; do not modify the live file directly.
